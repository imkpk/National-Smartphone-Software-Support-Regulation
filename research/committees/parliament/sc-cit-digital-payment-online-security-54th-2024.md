# Parliamentary Report Note — Digital Payment and Online Security Measures for Data Protection

## 1. Report title [FACT]

**Fifty-Fourth Report** — Standing Committee on Communications and Information Technology (2023–24) on **Digital Payment and Online Security Measures for Data Protection**, relating to the **Ministry of Electronics and Information Technology**.

## 2. Committee / Commission [FACT]

Department-related Parliamentary Standing Committee on **Communications and Information Technology** (Seventeenth Lok Sabha).

## 3. Publication year [FACT]

**2024** (presented to Lok Sabha / laid in Rajya Sabha on **08 February 2024**). Lok Sabha Secretariat, New Delhi.

## 4. Scope [FACT]

Subject examination covering (as per official contents):

1. Introductory  
2. Growth of digital payments, acceptance infrastructure, and payment ecosystem  
3. Cyber fraud landscape and statistics  
4. Existing framework of cyber security and related issues  
5. Steps taken to develop robust security mechanisms for digital payments  
6. Observations/Recommendations  

Official PDF: https://sansad.in/getFile/lsscommittee/Communications%20and%20Information%20Technology/17_Communications_and_Information_Technology_54.pdf?source=loksabhadocs  
Access date: **2026-07-30**. [T1]

## 5. Key findings [FACT]

From the official report (orientation + text confirmed on access):

- Digital payments expansion increases the stakes of cyber fraud and data protection.  
- Examines institutional cyber-security frameworks (including banking/RBI cyber security framework references in evidence).  
- Notes emphasis (via institutional evidence) on **maintaining up-to-date security**, application of latest patches, and avoiding **End of Life / End of Support software** in the **financial-institution / critical systems** context (as reported from RBI Cyber Security Framework 2016-related inputs in the report).  
- Focus is **payments ecosystem security and data protection**, not consumer handset product-regulation of OS support years.

## 6. Relevant recommendations [FACT]

Part-II of the report contains Observations/Recommendations (pp. 36–46 in the official pagination). Themes include strengthening digital-payment security and online data-protection measures under MeitY’s domain as examined.

**Not identified:** a recommendation that **smartphone manufacturers** must provide a fixed multi-year **consumer handset** OS upgrade or security-update support period as a product mandate.

## 7. Relevance to smartphone software support [ANALYSIS]

| Interface | Note |
|-----------|------|
| Patching culture | Report context reinforces that **unsupported/EoL software is a security risk** — primarily for financial/critical systems |
| Consumer handsets | Smartphones are primary digital-payment end-points; security of the payment stack intersects with device security **as a systems issue** |
| Distinction | Institutional patching guidance ≠ mandatory OEM multi-year support floors for retail Android/iOS devices |
| Gap | No identified multi-year OEM OS/security-support mandate recommendation |

## 8. Limitations

- Recommendations section should be annexed page-by-page for court-ready quotes.  
- RBI framework references in evidence are **not** converted into MeitY product standards by this report alone.  
- Statistics in the report are time-bound; use original tables for any quantitative claim.
