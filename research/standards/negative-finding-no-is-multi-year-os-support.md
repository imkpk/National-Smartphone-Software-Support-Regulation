# Negative Finding — Standards Layer (Phase 4 WS3)

## Repository Relevance

**Tags:** Technical Standard · Cyber Security · Electronics · Repository Cross Reference  

Analytical negative finding for the repository standards workstream.

## 1. Search performed [FACT]

| Authority / class | What was examined |
|-------------------|-------------------|
| BIS portal / prior BIS regulator note | Multi-year OS/security-support IS / QCO orientation |
| CERT-In | Directions (2022), Government Entities Guidelines, Secure Application Guidelines (CISG-2024-01), OEM AI vulnerability guidelines listing (CISG-2026-03) |
| MeitY | Electronics standards / CRO pathway orientation |
| DoT | Not expanded as separate standards corpus this pass (equipment deep-dive residual OPEN / TEC) |

**Date:** 2026-07-31  

## 2. Evidence reviewed [FACT]

- Official CERT-In portal guidelines listings and selected PDF/portal materials  
- BIS institutional pathway (portal + Phase 3 note)  
- MeitY electronics standards pathway  
- Repository cross-links to Phase 2–3 statutes/regulators  

## 3. Conclusion [FACT]

**No official Indian Standard (IS), Quality Control Order, or CERT-In guidance reviewed in this workstream was identified that establishes a mandatory multi-year minimum period of operating-system upgrades and/or security updates that smartphone manufacturers must provide for consumer devices sold in India.**

CERT-In materials reinforce **security practices, incident reporting, application security, and OEM vulnerability-response guidance (catalogue level)** — not a multi-year retail OS support floor as identified.

## 4. What this is not

- Not a claim that no future IS/QCO can be made.  
- Not a claim every IS PDF was OCR’d.  
- Not legal advice.
