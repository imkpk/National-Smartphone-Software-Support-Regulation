# Negative Finding Protocol Result — Minimum Smartphone Software Support Mandate

## 1. Research question [OPEN → addressed]

Is there a binding all-India statute, rule, or quality-control order that **expressly requires** a minimum number of years of operating-system upgrades and/or security updates for smartphones sold in India?

## 2. Search protocol [FACT]

| Step | Action | Date |
|------|--------|------|
| 1 | Review CPA 2019 structure (India Code PDF) for product liability / UTP—no multi-year update mandate found | 2026-07-30 |
| 2 | Review IT Act 2000 framework for CERT-In—cybersecurity institutions, not OEM OS floors | 2026-07-30 |
| 3 | Review EPA 1986 + E-Waste Rules 2022 public scheme—EPR/collection focus | 2026-07-30 |
| 4 | Review BIS Act 2016 pathway—standards/QCO possible but no identified IS/QCO on OS support years | 2026-07-30 |
| 5 | Review Legal Metrology packaging declaration scheme—no OS-support year field identified | 2026-07-30 |
| 6 | Keyword orientation: “software support”, “security update”, “operating system” in connection with smartphone product mandates | 2026-07-30 |

**Portals used:** India Code (indiacode.nic.in); CERT-In (cert-in.org.in); CPCB/MoEFCC public pages; BIS (bis.gov.in). [T0/T1]

## 3. Finding [FACT]

**As of 2026-07-30, this research workstream did not identify** a dedicated, binding all-India legal instrument that states:

> “Smartphones sold in India must receive X years of OS upgrades and/or security updates.”

Related instruments address **consumer protection**, **cybersecurity institutions**, **e-waste EPR**, **standards infrastructure**, and **packaging metrology**, which may **interface** with software-support *policy design* but do not, on the materials reviewed, create that express mandate.

## 4. What this finding is not [ANALYSIS]

- Not a claim that no future rule can be made.  
- Not a claim that consumer law never applies to update misrepresentations.  
- Not a claim that every possible notification was exhaustively OCR-searched—**residual search risk remains** (OPEN).  
- Respondents may produce an instrument not located here; pleadings should invite them to do so.

## 5. Residual search recommendations [OPEN]

2. BIS catalogue search for mobile OS / security labels.  
3. RTI to MeitY/BIS/DoT on any draft standard on software support.  
4. Full-text Gazette search for “security update” + “smartphone”.
